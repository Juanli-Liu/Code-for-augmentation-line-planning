# 测试输入数据约定

当前主程序默认读取 `Test_data_complex`；要读取本目录，修改 `main.cpp` 的
`kInputDataDirectory` 并重新编译。主程序不接收数据目录或 `--report-input`、`--solve-*` 参数。
当前统一验收请从项目根目录运行 `scripts/run_baseline.ps1`，它会同时验收三个算例，
无需修改主程序的输入常量。完整运行方式与固定基线见 [项目说明](../../README.md)。

本目录用于主问题及第一层非周期时刻表验证。所有时间数值均为 time_step，当前每步为 1 分钟，规划时域为 0～240（含两端）。PDF、PNG 为校验图，不作为模型输入。

## 全局参数与停站

- `existing_train_max_delay=5`：测试用统一后移上限，即每列既有列车每个实际到达/出发事件相对本版已公布时刻最多后移 5 分钟，禁止提前。它不是全列车延误总预算；以后可扩展逐车差异。
- `minimum_stop_platform_occupation_time=4`：中间停车站的最小停站时间。
- `minimum_terminal_platform_occupation_time=15`：始发前、终到后各自的最小占轨时间，独立于动车组折返时间。
- `startup_additional_time=2`：从停车状态出发的起车附加时分。
- `stopping_additional_time=3`：到达停车站的停车附加时分。
- 所有候选线路均可使用 `long`、`short` 两类动车组，容量依用户约定分别为 550、1100；备用数量分别为 2、1，允许频率统一为 1、2。

## 区间运行时间（既有与新增共用）

`sections.csv` 的 `pure_running_time` 只存纯运行时间。A—B、B—C、C—D、D—E 分别为 13、15、17、15 分钟，双向相同；各有向区间 `maximum_train_count=8`。

`sections.csv` 的必填列 `direction` 指定有向区间的运行方向，`up` 表示上行，`down` 表示下行。当前算例从 A 经 B、C、D 至 E 的各有向区间填 `down`，反向区间填 `up`。一条线路的各区间须同向，既有与新增列车均从所属线路取得方向。

对列车 i 经过有向区间 (s,s')，代码按停站方案计算：

    running_time(i,s,s') = pure_running_time(s,s')
                        + 2 * stops(i,s)
                        + 3 * stops(i,s')

其中 `stops` 为 0/1，包括始发、终到站均为 1。不区分编组。起车时分只加在出发区间，停车时分只加在到达区间，不重复计入停站时间。

例如 A→B：停→停为 18 分钟，停→通为 15 分钟，通→停为 16 分钟，通→通为 13 分钟。相同区间因停站状态不同而有不同的实际运行时间，这是预期行为。

本版测试基准将 100、101 各后移 5 分钟，200、201 各后移 3 分钟，104 提前 4 分钟，204 提前 9 分钟。整趟平移保持区间运行时间和中间停站时长，使 15 分钟的端点占轨和列车间隔均可容纳在规划时域内。5 分钟后移窗口以本版公布实际时刻为基准。

## 候选线路与可选轨道

`lines.csv` 在当前四种既定路径上枚举全部中间站停通组合，始终点必停：A→E、E→A 各 8 种，B→D、D→B 各 2 种，共 20 条。原有 line_id 0～5 保留，新增使用 6～19。此枚举不额外增加其他始终点路径。

`line_allowed_platforms.csv` 包含 92 条线路—车站记录。停站仅可选择同向 t 轨道：下行 t1/t3，上行 t2/t4；通过仅可使用同向正线：下行 b1，上行 b2。多个 ID 与名称按相同顺序以分号分隔。

候选方案 `(line,frequency,formation)` 由代码生成：20×2×2=80 个原始组合。既有列车不要求一一对应候选线路；它们的路径及固定轨道直接从既有时刻表恢复。

## 既有时刻表与轨道资源

`timetable.csv` 保留模板五列。`Paths` 中每站连续两个相同的“站名-轨道名”，用于标识固定轨道。`Times` 依次记录实际始发、各中间站的实际到达和出发、实际终到，条目数比 `Paths` 少两个。中间通过站的到发时刻相等。加载器按实际始发减端点参数、实际终到加端点参数派生基准开始占轨和释放轨道。旧表若仍包含首末占轨槽位，加载时会跳过这两个值。加载器校验全部实际时刻和派生边界在 [0, planning_horizon] 内。后移窗口适用于公布的实际到发时刻。

主问题既有轨道资源 `B0` 按每次访问累加。始发和终到各计 15，中间停车取公布出发减公布到达，通过取 `minimum_pass_platform_occupation_time=2`。候选车次逐站最小资源时间为端点 15、中间停车 4、通过 2。

通过站的安全资源时间 2 不转化为停站时间：第一层通过活动仍满足 departure-arrival=0。`track_headway=2` 单独用于第一层同轨相邻活动的间隔约束；计算 B0 时不再额外重复叠加这个参数。主问题资源计量与第一层事件时间的物理含义不同。

既有区间车次数按本表的有向相邻站计数，在代码中计算，不再输入一份副本。

## 代码派生的时间与集合

- OD 只可选择起终点均停车且方向正确的候选服务，不考虑换乘。
- 旅客旅行时间 `t_od_a` 为从 OD 上车站实际出发到下车站实际到达的最短行程：沿途实际区间运行时间之和，加两站之间的中间停站时间，不含上车前及下车后的站线占用。
- 最短任务时间 `T_a` 同样按线路始发时刻至终到时刻计算，包含全部实际区间运行时间及中间停站时间，不含始发前、终到后占轨时间；折返时间由动车组工作量约束另计。
- 对每个 OD，`shortest_travel_time` 为可用服务旅行时间的最小值，单位未满足惩罚为该值乘 alpha。每种停站方案改变后须重新计算，不能沿用全停线路时间。
- C++ 加载器按 OD 业务编号读取基础记录，再为每条候选线路生成各相邻停车区段覆盖的 OD 列表。候选方案共用所属线路的座位区段映射。加载器也生成逐车次任务、OD 服务集合及旅行时间。

频率 2 可以通过单独候选方案的区间容量检查。多个候选的联合容量由主问题约束，具体车次的可插入性由时刻表验证层判断。

可用绘图脚本按本版时刻和派生占轨边界生成 `timetable_diagram_integrated_240min_start_stop.pdf`。随目录保存的旧图对应先前基准。

校验入口：`scripts/validate_input_data.py`；绘图入口：`scripts/plot_existing_timetable.py`。它们用于核查输入；实际 C++ 模型应遵循以上同一规则。

## C++ 数据加载入口

主程序调用 `LoadProblemData` → `RunPlanningIteration`，由参数表选择第一层 MILP 或 SAT，
已证不可行时追加完整候选集合割并重求。`copt_smoke_test.cpp` 保留但不参与主项目编译。

加载器按业务 ID 排序建立连续内部编号；业务 ID 不要求连续。`ProblemData` 拥有全部对象，ID 映射与对象间指针均为非拥有引用。候选线路 index 从 0 开始，既有专用线路接在候选线路之后；列车 index 先既有、后新增，因而不能将新增列车 index 直接当作 `added_trains` 下标。候选按线路业务 ID、频率升序、车型 long/short 顺序生成；候选内 `trains` 顺序即任务序号。既有列车业务 ID 按字符串排序，其他业务 ID 按非负整数排序。

当前输入生成 80 个候选、120 个备选新增任务。加载阶段保留全部候选，由主问题按资源约束选择。既有列车的到发线固定，基准时刻与受限后移参数分别保存，加载期间不调整时刻。

`Train::published_arrival_times` 和 `published_departure_times` 保存沿途各站实际到发基准时刻，首站到达、末站出发为空。另用两个可选标量 `published_start_track_occupation_time`、`published_end_track_occupation_time` 分别保存始发站开始占轨、终到站释放轨道的基准时间。中间站占轨边界直接取对应到发时刻，不重复存储。通过站实际到达与出发相同，2 分钟安全资源计量不会转化成停站时间。新增任务的公布时刻、固定轨道和始终点占轨字段全部为空。首尾的 `minimum_dwell_times` 为 0，始终点最小占轨另由候选的轨道占用参数表达。

加载失败返回 `InputError`，包含文件、记录行号及相关字段。输入采用 UTF-8（可含 BOM）；支持带引号、逗号、转义双引号及换行的 CSV 字段。OD 若没有直达候选，则报告无法依据候选计算最短旅行时间与惩罚；未来若需保留此类 OD，应另行定义外生惩罚参数。

## 当前求解与报告

`master_problem` 建立持久 COPT 模型，输出目标分解、候选及 OD 分配；
`timetable_data` 根据选中候选生成具体车次、事件、活动、可用轨道、同向车站冲突及区间次序。
实际到发与始终点占轨边界分开建模，只有既有实际到发事件直接受公布时刻和后移上限约束。

第一层 MILP 与 SAT 使用同一份时刻表数据。MILP 的事件时刻为整数，使用时间域计算 big-M；
SAT 使用时间顺序编码。两者均检查运行等式、停站/端点占轨下界、通过等式、同向安全间隔、
区间禁越行、唯一轨道分配和同轨占用兼容；提取见证后，均调用正式的独立约束检查器。
第一层不优化延误，时刻表可能包含超过下界的停站或占轨，两个后端的具体见证可以不同。

当前求解控制参数如下；数值对应本目录 parameters.csv，其他算例有各自的预算。新增割模式和复核预算已显式列入参数表，加载器仍兼容省略这两项的历史输入。

| parameter | 本目录 value | unit |
|---|---|---|
| maximum_rounds | 100 | round |
| total_time_limit_seconds | 3600 | second |
| master_time_limit_seconds | 300 | second |
| master_solver_logging | 0 | boolean |
| timetable_solver | 1 | backend（1=MILP，2=SAT） |
| conflict_cut_mode | 1 | mode（1=完整集合割，2=assumptions直接核；2要求SAT） |
| core_verification_time_limit_seconds | 60 | second（子集重建与复核预算） |
| timetable_time_limit_seconds | 60 | second |
| timetable_solver_logging | 0 | boolean |
| planning_output_root | results | path |

修改参数后重新运行即可生效，无需重编译。时限为秒，不受 time_step_minutes 换算；
MILP 单次预算限制 COPT 求解，SAT 单次预算包含编码和搜索。完整流程还受总墙钟预算限制，
阶段间检查剩余时间；建模和报告写入不能硬实时抢占。相对输出路径基于进程工作目录。

每次运行产生独立 run_* 目录，包含 configuration.txt、round_1.txt 等逐轮报告及 summary.txt。
报告记录主问题、时刻表输入、后端与判定、见证、割和终止原因。
持久主问题只建立一次静态模型，追加割后在原模型上重求；第一层 SAT 当前每轮重建。

第一层已证不可行且选中集合 C 非空时，默认加入完整集合割 sum(x_a, a in C) <= |C|-1。
可选参数 `conflict_cut_mode,2,mode` 启用 assumptions 直接核（要求 `timetable_solver=2`）；
`core_verification_time_limit_seconds,60,second` 设置独立子集复核预算。省略两项时默认1和60，
因此历史输入无需修改。核必须独立重建并复核 UNSAT 才加割；提核或复核失败回退完整集合。
原问题未定或异常不加割；空核复核若证明既有背景不可行，则停止且不生成空集合割。
详细配置见 [直接提核说明](../../tests/README_assumptions.md)。

正式程序退出码：0=第一层可行，3=已证不可行，4=未定或达到轮数/时间限制，1=错误。
主问题未证最优时只报告可行方案；第一层可行不代表动车组交路已经验证。
